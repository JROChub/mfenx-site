Receipt fields can still disclose model identities, evaluation counts and an issuer name. Treat a receipt as business information. Selective sharing is not anonymity.

The admission boundary

The receipt verifier checks the selected issuer key, signature, schema, validity and commitments. The consuming deployment must also pin the approved policy and load the same artifact bytes that were checked.

A release pipeline can block publication after a failed local evaluation. It does not prevent an operator with unrestricted host access from running a different executable. Keep signing credentials and policy approval separate from untrusted model submissions.

Controls to configure

Download and authenticate the organization runtime. The installation guide includes publisher trust pins, offline installation and the installed acceptance procedure.

SDK software inventory · CycloneDX 1.6 · Inventory validation record

Define key ownership, rotation, expiry, approved contract digests, release permissions and recovery procedures. Package the exact runtime and its dependencies for an offline deployment; acceptance must execute inside that target environment.

The optional organization service runs in the customer environment with customer-controlled authentication, storage, TLS and backups. Software licensing is separate from model admission and receipt verification; it does not send organization records to MFENX. Browser verification itself has no account database, advertising code or file-upload endpoint.

An asynchronous review

Begin with the current runtime security record and the assurance definitions. The product’s third-party notices remain attached to the relevant components. Paid internal use follows the commercial terms and any applicable order. Deployment-specific data agreements and requested tax forms are separate documents; they are not implied by a technical receipt.
