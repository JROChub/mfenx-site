Deploy a contract

Compile Solidity with the EVM target set to cancun. Sign locally with chain ID 2026092601, transaction type 2, maxFeePerGas = 0 and maxPriorityFeePerGas = 0. Use the sender’s next nonce and a gas limit at or below 3,000,000. Contract creation leaves the destination unset and places the initcode in the data field.

Submit the signed bytes using eth_sendRawTransaction. Poll eth_getTransactionReceipt; status: 0x1 indicates success, while status: 0x0 records a reverted or halted execution. A failed included transaction advances the nonce but rolls back contract changes. Signing keys remain in your wallet or local signer.

eth_call simulates without committing state. eth_estimateGas returns a gas limit tested by simulation, rather than a fixed placeholder. eth_getCode, eth_getStorageAt and eth_getLogs expose the finalized execution result.

The public gateway admits signed transactions at a sustained rate of one every five seconds, with a short burst allowance. Initcode and calldata are limited to 49,152 bytes; signed transactions to 51,200 bytes. Log queries cover at most 128 blocks and 256 matching records. The runtime manifest publishes the resource limits.

Reproduce acceptance

Release 20261008.3 retains the existing Power House license and separates the validator runtime from the published Power House 0.4.0 crate. The source archive includes the pinned dependency lockfile and the standalone ledger validation tool. This tool verifies signatures, replays native and contract transactions, and checks every committed state root and execution receipt.

Download the corresponding validator source and the ledger above. With Rust 1.93.1:

mkdir mfenx-validator-source
tar -xzf validator-execution-20261008.3.tar.gz -C mfenx-validator-source
cd mfenx-validator-source
cargo build --locked --release --features net --example native_release_tool
./target/release/examples/native_release_tool validate-state ../execution-20261008-ledger.json

The acceptance suite passed 112 Rust library tests and 58 gateway tests. A three-process integration run tested deployment, nested calls, historical reads, logs, rollback, gas exhaustion, large signed payloads, mutation rejection and restart recovery. The live record covers the deployed Solidity contract, both TLS RPC routes and identical receipts on all three validators.

Consensus and state format

MFENX uses its native Ed25519 validator consensus with a two-of-three quorum. The three processes currently share one host. Cancun instruction semantics run under the fee-free MFENX profile; network blocks and state use MFENX’s native formats.

mfenx-evm-contract-state-v1 commits to canonical sorted accounts, bytecode and storage using a domain-separated Keccak digest. It is not an Ethereum Merkle Patricia trie. BLOCKHASH reads finalized MFENX block hashes; PREVRANDAO uses the parent hash and is not a randomness beacon. Query mfenx_getExecutionProfile to inspect the active profile and transaction admission status.
